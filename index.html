Many beginners slap "use client" on the whole app, then wonder why performance tanks & bundle size explodes. One glance at the comic and you'll get it! 👇 🌟 1. Server Components (the default!) ✅ Pros: fetch DB directly on the server, safely use API keys, zero bundle size — super fast! ❌ Limitation: renders to HTML on the server, so no interactivity! 🌟 2. Need interactivity? If your component uses event listeners (onClick), state hooks (useState), browser APIs (window) or useEffect... 👉 A Server Component can't do it — it'll throw an error! 🌟 3. The magic spell: "use client" Just add "use client" at the top of the file and Next.js turns it into a Client Component — all interactivity is back! ✨ 🌟 4. Best practice: Server first, Client when needed! Don't mark your whole app as "use client"! The right way: 👉 Keep the main structure as Server Components 👉 Only extract the interactive parts into Client Components and nest them back (Leaf Node strategy) Perfect balance of performance & interactivity! ⚖️ 💡 Quiz of the day: You wrote a component that only displays a name — no clicks, no state.
